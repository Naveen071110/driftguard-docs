---
title: "Create Webhook"
description: "Register a webhook endpoint that DriftGuard will POST to when a check completes."
---

## Endpoint
```http
POST /api/v1/webhooks
Host: api.driftguard.dev
```

---

## Request
```bash
curl -s -X POST https://api.driftguard.dev/api/v1/webhooks \
  -H "X-API-Key: $DRIFTGUARD_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://hooks.slack.com/services/your/slack/webhook",
    "events": ["breaking", "warning"],
    "contract_id": null
  }'
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `url` | string | ✅ | The HTTPS URL DriftGuard will POST check results to. HTTP URLs are rejected. |
| `events` | array | ✅ | List of result types that trigger this webhook. Valid values: `breaking`, `warning`, `pass` |
| `contract_id` | string \| null | ❌ | Scope this webhook to a single contract ID, or `null` to fire for all contracts |

<Warning>
  The `url` must use HTTPS. Plaintext HTTP endpoints will be rejected with a `400` error.
</Warning>

---

## Response
```json
{
  "id": "your_webhook_id_here",
  "url": "https://hooks.slack.com/services/your/slack/webhook",
  "events": ["breaking", "warning"],
  "contract_id": null,
  "active": true,
  "created_at": "2026-03-01T19:22:00Z"
}
```

### Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier for this webhook |
| `url` | string | The HTTPS endpoint DriftGuard will deliver payloads to |
| `events` | array | Result types that trigger this webhook |
| `contract_id` | string \| null | Contract scope — `null` means all contracts |
| `active` | boolean | Whether this webhook is currently active. Newly created webhooks are always `true` |
| `created_at` | string | ISO 8601 timestamp of when the webhook was registered |

<Warning>
  The `secret` signing key is **not currently returned** by this endpoint — this is a known bug.
  Signature verification via `X-DriftGuard-Signature` is therefore not yet usable.
  Watch the [Changelog](/changelog) for when the fix ships; once resolved, the secret will be
  returned once at creation time and never again.
</Warning>

---

## Delivery Behaviour

DriftGuard delivers webhook payloads in a background thread with automatic retries:

| Attempt | Delay |
|---------|-------|
| 1st (initial) | Immediate |
| 2nd retry | 5 seconds after failure |
| 3rd retry | 25 seconds after failure |

After 3 failed attempts the delivery is abandoned. Ensure your endpoint returns
a `2xx` response within a reasonable timeout to confirm receipt.

---

## Error Responses

| Status | Meaning |
|--------|---------|
| `400` | Invalid request body — missing `url`, non-HTTPS URL, or invalid event type |
| `401` | Missing or invalid `X-API-Key` |
| `429` | Rate limit exceeded — 100 req/min per key |
